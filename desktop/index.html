COMMAND LINE

Scriptable, JSON-speaking, cron-ready.

The desktop app is a thin shell over the same CLI. Point your automation at it directly — secrets come from environment variables, results come back as JSON, and every destructive operation is dry-run by default.

portabase doctor              # readiness checks; exit 2 on missing pieces
portabase probe --target db   # single JSON line: {"ok":true,...} — token|db|storage|tools|all
portabase backup --json       # capture+encrypt+transfer+verify; last stdout line is JSON
portabase backup --progress   # stream "@portabase {...}" machine events while running
portabase status              # last durable result as JSON; exit 5 unless healthy
portabase verify --decrypt    # checksums + authenticated decryption proof
portabase restore --capsule DIR                  # no-write recovery plan
portabase restore --capsule DIR --preflight      # plan + live blank-target checks
portabase restore --capsule DIR --execute \
  --confirm-target NEW_REF --json                # guarded write, evidence as JSON
portabase prune --keep 30 --execute              # guarded retention

Secrets (environment only, never written to disk by the CLI):
  SUPABASE_DB_URL  SUPABASE_URL  SUPABASE_SERVICE_ROLE_KEY
  SUPABASE_ACCESS_TOKEN  PORTABASE_ENCRYPTION_PASSPHRASE
Exit codes: 0 ok · 1 failure · 2 doctor gaps · 3 partial capture ·
            4 verify failure · 5 unhealthy status · 6 probe failure

Config lives in portabase.config.json; schedule with cron/systemd/schtasks calling backup. The install-schedule command prints the exact entry.
